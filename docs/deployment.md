# Production deployment

No hosting account, provider resource, credential, external teacher approval or real deployment is created by this repository.

1. Create a Supabase project in an appropriate region. Enable email confirmation, configure authenticated SMTP delivery and password rules, and set the site/redirect URLs to your HTTPS application URL. Add that project's URL and publishable key to environment settings. Add its service role key server-side for authentication-account erasure.
2. Add the Supabase PostgreSQL connection URL as `DATABASE_URL`, server-side. Use its documented pooler/connection mode; the application disables prepared statements. TLS certificates are verified. If the database requires a supplied CA, obtain it through the provider's official documentation and set `HABIB_DATABASE_CA_PATH` to that certificate file. Do not disable verification.
3. Apply `npm run db:migrate` with that database configuration. The migration is versioned and transactional; it enables RLS on every application table, gives authenticated parents access only to their own selected data, and denies direct browser writes. Route handlers enforce ownership, consent, entitlement and input validation using the backend connection.
4. Configure Supabase email templates with explicit token-hash links. Signup confirmation link: `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}`. Password recovery: `{{ .SiteURL }}/reset-password?token_hash={{ .TokenHash }}`. The recipient explicitly confirms or sets a password before the app exchanges the token. Test confirmation, expired links, password reset and SMTP delivery in staging.
5. Create an Azure Speech resource and securely set `HABIB_SPEECH_KEY` and its region. Allow `<region>.stt.speech.microsoft.com` and `<region>.tts.speech.microsoft.com` for server HTTPS egress. Perform the Maltese voice evaluation in the release-gates document; listing a voice does not establish child-speech accuracy.
6. Add an OpenAI project key as `HABIB_OPENAI_KEY`; allow `api.openai.com`. Set model identifiers supported by that account. Test arithmetic photos, ambiguous images and image prompt injection. Images are not stored.
7. Create a Stripe sandbox product/recurring EUR price. Set `STRIPE_SECRET_KEY`, `STRIPE_FAMILY_PRICE_ID`, `STRIPE_WEBHOOK_SECRET`, `HABIB_FAMILY_PRICE_EUR` and `HABIB_MONTHLY_VOICE_MINUTES`. Align displayed pricing with the Stripe price. Enable the Stripe customer billing portal. Register `/api/v1/billing/webhook` for checkout completion, subscription created/updated/deleted, invoice paid and invoice payment failed. Use separate sandbox and live environments. Secrets are server-only. Do not use proxy-placeholder secrets for local webhook HMAC checks: the webhook signing secret must be available as an actual secure runtime value.
8. Deploy to your own Vercel project using Node 24. Set `APP_ENV=production`, `NEXT_PUBLIC_APP_URL` to the canonical HTTPS origin, and a secure `HABIB_INVITE_CODE` for invitation-only signup. Vercel always enforces production mode; it cannot fall back to SQLite. Allow the required database hostname and provider destinations. Database connections use the PostgreSQL protocol, so ensure the hosting/network route supports it; an HTTPS proxy secret is insufficient for a database connection string.
9. Review each topic with a teacher and native Maltese speaker; record verified curriculum outcome mappings with the curriculum CLI. Production cannot start unreviewed lessons. Approvals are administrative CLI operations, not browser endpoints. Set up restricted operator access and retain review/audit records.
10. Schedule the retention CLI at least hourly from a secure worker with database access. Install operational alerting for structured `request_error` and `speech_recognised` log signals, provider spend and latency, failed webhooks and infrastructure health. Logs never contain child transcripts, audio, images or credentials. Choose thresholds based on measured pilot traffic.
11. Complete the release gates, vendor contracts, final legal notices, parental-verification procedure, safeguarding escalation, backup/restore tests and incident-response plan before a supervised pilot. Invite one internal parent account first. Test real devices and withdraw consent mid-session. Use sandbox payments until all billing scenarios pass.

Deploying on Vercel and linking provider accounts requires the owner's hosting/provider access. Live subscriptions, external messaging and production launch must be authorised separately. Configuration fields saved during cloud onboarding do not publish a web app.

## Billing behaviour

Every new parent gets a 7-day trial with 5 metered voice minutes. Paid entitlement is granted only by verified webhook state. Cancel-at-period-end retains access until the period ends; past-due, unpaid, expired and cancelled states deny new tutoring. Current subscription state is retrieved from Stripe when processing supported events, protecting against stale payloads. Duplicate event IDs are ignored in a database transaction. Checkout uses a parent/period idempotency key to prevent duplicate creation on repeated clicks. Trial and paid usage are separate period keys.

## Operational limitations

All local/cloud database changes are serialized with a transaction lock for conservative correctness. This is suitable for an initial controlled pilot; load testing and a per-family locking design are required before wider rollout. A recognition/synthesis operation reserves bounded quota before calling Azure. Raw recordings are never persisted, and generated audio is cached only briefly. A successful recognition consumes audio duration even if the tester subsequently discards its transcript. Provider outages and abusive retry patterns still require project-level budgets and alerts.

## Conversation validation

Test natural Maltese follow-up questions, photo confirmation, conversational context, low-confidence recognition and manual interruption on real phones. Conversation uses Azure recognition, OpenAI text generation and Azure synthesis in separate bounded requests. It does not use the OpenAI Realtime API. Images remain restricted to supported mathematical types; chat remains a primary-school maths tutor. Automatic voice sends require confidence of at least 0.85; evaluate and calibrate this threshold with held-out Maltese speech before a child pilot. Test poor connections and browser autoplay gating. No new database migration is needed for this update: homework remains in the existing JSON field.
